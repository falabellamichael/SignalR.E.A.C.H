# RCCL peer transport probe, 2026-10-24

## Deployment outcome

Applied `NCCL_P2P_DISABLE=0` and `HSA_ENABLE_IPC_MODE_LEGACY=0` to live
Gemma after the probes. Startup and a chat smoke test passed with context
131072. Support identity/start time remained unchanged. The original container
is retained as `reach-gemma-before-p2p-20261024`, with automatic restart disabled.
The new container retains `unless-stopped`. Gemma launcher defaults now specify
both settings; end-to-end performance improvement remains unmeasured.

## Pre-change observations

The live Gemma container uses NCCL_P2P_DISABLE=1 and
HSA_ENABLE_IPC_MODE_LEGACY=1. ROCm reports peer access in both directions
between the gfx1201 GPUs; topology is PCIe, two hops.

Two-rank PyTorch/RCCL all-reduce probes ran in separate processes inside the
existing container, without changing the serving processes' environment.
Each message size had five warmup and twenty measured iterations. Float32
rank inputs 1 and 2 were checked for an exact sum of 3 on both ranks on every
iteration. Sizes: 1 KiB, 16 KiB, 256 KiB, 4 MiB, 16 MiB. Runs were bounded
by a 120-second process timeout and a 45-second process-group timeout.

## Findings

- Existing settings work, with logs showing `SHM/direct/direct` transport.
- P2P enabled with legacy IPC retained fails at `hipIpcGetMemHandle` with
  `invalid argument`. Peer capability alone does not establish IPC usability.
- P2P enabled with `HSA_ENABLE_IPC_MODE_LEGACY=0` works. Logs explicitly show
  `P2P/IPC` in both directions. Both full runs passed numerical checks.

Median all-reduce latency, milliseconds (first run / repeat):

| Size | Existing SHM | P2P with legacy IPC disabled |
| --- | --- | --- |
| 1 KiB | 0.155 / 0.106 | 0.115 / 0.089 |
| 16 KiB | 0.116 / 0.124 | 0.105 / 0.089 |
| 256 KiB | 0.129 / 0.131 | 0.109 / 0.094 |
| 4 MiB | 0.415 / 0.413 | 0.311 / 0.291 |
| 16 MiB | 1.249 / 1.240 | 0.932 / 0.908 |

This supports a controlled serving trial of both environment changes together.
It does not establish an end-to-end model speedup, sustained P2P reliability,
or equivalence across tensor dtypes and collective shapes. Microbenchmarks ran
alongside resident serving processes rather than on exclusive GPUs.

RCCL warns that `iommu=pt` is absent. This is a VM; the warning alone does not
establish the host IOMMU configuration or explain the failure. No boot or
driver settings were changed. SDMA, channels, protocol, and runtime libraries
were held fixed.
